# BIM 现有系统 OTC 融合规划方案书

> 文档状态：待产品、运营、合规与技术评审  
> 当前阶段：仅规划，尚未实施  
> 适用系统：现有 BIM Flutter 客户端、TP8 业务后台、钱包体系、服务号、Gateway 实时链路  
> 版本：V1.0  
> 编制日期：2026-07-11

## 1. 文档目的

本方案用于规划 BIM 现有系统中的 OTC 数字资产买卖能力。OTC 不是独立应用、独立后台或另一套用户体系，而是原生接入当前 BIM：

- 客户端继续使用“消息、联系人、发现、我的”四个主入口。
- OTC 主要入口放在“我的 - 钱包”。
- 用户、登录设备、支付密码、账号安全和钱包风控继续复用现有能力。
- TP8 后台在现有钱包管理体系内增加 OTC 管理。
- OTC 订单通知通过现有服务号和 Gateway 实时下发。
- 订单聊天复用现有实时消息能力，但使用独立业务内容类型和保存规则。
- 本地缓存继续使用当前加密存储方案，不增加第二套客户端存储框架。

本文件只确定业务边界、架构、状态机、数据和安全原则。评审通过前不创建数据库、不增加接口、不改客户端页面。

## 2. 评审范围

### 2.1 本方案包含

- 数字资产与网络配置
- 用户数字资产账户和地址簿
- 用户法币收款方式
- 商家申请、认证、保证金和等级
- 商家买入/卖出广告
- 用户买币和卖币
- 优质商家匹配
- OTC 托管、冻结和资金账本
- 订单状态机、超时和取消
- OTC 服务号和支付服务号分工
- Gateway 实时订单事件
- 订单聊天和交易证据
- 评价、申诉和后台仲裁
- 后台菜单、权限和审计
- 客户端页面和缓存规划
- 风控、安全和验收标准

### 2.2 本方案不代表已实现

以下内容在评审和合规确认前均视为未实现：

- 真实数字资产充值和提现
- 链上热钱包、私钥托管和自动归集
- 法币支付渠道自动查账
- 商家自动认证
- 自动仲裁和自动放币
- 任何特定国家或地区的上线许可

### 2.3 不采用的架构

- 不创建独立 OTC App。
- 不创建独立登录和用户表。
- 不创建独立支付密码。
- 不创建独立长连接。
- 不绕过现有钱包账本直接改余额。
- 不把数字资产余额塞进现有人民币余额字段。
- 不使用普通私聊承载 OTC 订单证据。
- 不依赖客户端判断资金状态。

## 3. 现有系统融合关系

| 现有模块 | OTC 接入方式 |
| --- | --- |
| Flutter 客户端 | 钱包增加买币、卖币、数字资产、OTC 订单和商家中心 |
| TP8 API | 增加 OTC 领域服务和安全接口，继续使用现有 API 域名 |
| 用户体系 | 使用现有 appid、user_id、usertoken、设备会话 |
| 账号安全 | 复用手机号、邮箱、验证码、支付密码和设备校验 |
| 法币钱包 | 保留现有余额、冻结、账单和钱包封控 |
| 服务号 | 增加 OTC 服务号；支付服务号继续负责资金通知 |
| Gateway | 下发订单、商家、广告和仲裁事件 |
| 消息系统 | 订单聊天走现有实时层，但使用独立订单频道和内容类型 |
| MMKV 缓存 | 缓存配置、订单、广告、资产和商家资料的加密快照 |
| TP8 后台 | 在现有后台导航中增加 OTC 管理，不建设第二套后台 |
| 日志系统 | 增加 otc、otc_order、otc_wallet、otc_risk 分类和 trace_id |

## 5. 产品入口和客户端信息架构

### 5.1 主导航不变化

继续保持：

```text
消息
联系人
发现
我的
```

OTC 不新增第五个底部导航项。

### 5.2 钱包入口

现有路径：

```text
我的 → 钱包
```

钱包页面规划：

```text
钱包
├── 资产总览
│   ├── 法币可用余额
│   ├── 法币冻结余额
│   ├── 数字资产折算
│   └── OTC 托管资产
├── 收付款
├── 买币
├── 卖币
├── 数字资产
├── OTC 订单
├── 账单
└── 商家中心
```

普通用户显示买币、卖币、数字资产、订单。商家中心根据状态进入申请、审核进度、缴纳保证金或商家工作台。

### 5.3 首页快捷菜单

首页右上角快捷菜单继续保持高频通用能力：

- 发起群聊
- 添加好友
- 收付款
- 扫一扫

第一期不把买币、卖币塞进首页快捷菜单，避免首页继续臃肿。后台可配置是否在“发现”增加 OTC 入口。

### 5.4 消息页

新增两类现有会话体系内的服务会话：

- 支付通知：资金入账、退款、手续费、保证金变动。
- OTC 交易：订单创建、付款、放币、申诉、仲裁等业务状态。

会话摘要示例：

```text
[OTC] 等待买方付款
[OTC] 对方已标记付款
[OTC] 数字资产已释放
[保证金] 已缴纳 ¥10,000.00
```

## 6. 钱包账户体系

### 6.1 现有法币钱包保持不变

继续使用现有：

- 可用余额
- 冻结余额
- 钱包锁定
- 支付密码
- 账单
- 收付款码
- 后台余额冻结和解冻

OTC 不改变现有法币余额含义。

### 6.2 新增数字资产子账户

每个用户、数字资产、网络独立账户：

```text
可用数量
冻结数量
OTC 托管数量
充值待确认数量
提现处理中数量
版本号
```

建议表：`wallet_asset_account`。

核心唯一键：

```text
appid + user_id + asset_id + network_id
```

### 6.3 商家保证金账户

保证金必须独立于法币余额和数字资产余额：

```text
保证金总额
可用保证金
冻结保证金
扣罚保证金
待退保证金
```

保证金的缴纳、冻结、扣罚、补缴、申请退还和实际退还全部生成账本流水。

### 6.4 金额精度

- 法币：`DECIMAL(36,8)`，展示精度由法币配置决定。
- 数字资产：`DECIMAL(65,30)`，展示精度由资产和网络配置决定。
- 服务端和客户端使用十进制定点字符串。
- 禁止使用 float/double 执行资金计算。

## 7. 数字资产与网络

### 7.1 数据模型

```text
数字资产 USDT
├── TRON / TRC20
└── Ethereum / ERC20
```

客户端不写死两个网络。后台初期启用两个，但数据库和接口支持继续扩展。

### 7.2 网络配置

后台字段：

- 资产代码和显示名称
- 网络代码和显示名称
- 合约地址
- Token decimals
- 地址校验规则
- 是否需要 Memo/Tag
- 最小充值和提现
- 提现手续费
- 普通确认数和高风险确认数
- 区块浏览器地址模板
- 是否允许充值、提现和 OTC
- 维护状态

资产身份必须使用：

```text
asset_id + network_id + contract_address
```

不能只使用 USDT 字符串判断网络。

## 8. 用户数字资产地址

### 8.1 地址管理入口

```text
我的 → 钱包 → 数字资产 → 选择资产 → 地址管理
```

用户可保存：

- 默认收币地址
- 备用地址
- 网络
- Memo/Tag
- 地址备注
- 二维码
- 最近使用时间

### 8.2 买币时选择地址

选择顺序：

1. 选择数字资产。
2. 选择网络。
3. 选择已保存的匹配地址。
4. 没有匹配地址时手动填写。
5. 或使用扫一扫、相册二维码识别。
6. 服务端校验网络、地址、Memo 和风险状态。
7. 用户二次确认完整地址。

复用现有扫一扫，不创建第二套扫码页面。扫码结果类型扩展为：

```text
friend
payment
crypto_address
otc_order
```

### 8.3 地址安全

- 地址网络不匹配时禁止创建订单。
- 地址完整值不写普通日志。
- 新地址、大额地址和高风险地址进入额外审核。
- 修改默认地址需要安全验证。
- 订单创建时保存地址快照，之后修改地址不能改变进行中订单。

## 9. 法币收款方式

用户和商家可绑定后台允许的方式：

- 支付宝
- 微信
- 银行卡
- 平台法币余额

收款账户姓名必须与认证主体一致。收款方式修改后设置冷静期，进行中订单继续使用订单创建时的快照。

银行卡字段：

- 持卡人姓名
- 银行名称
- 卡号
- 开户支行
- 国家/地区
- 法币
- 单笔和日限额

支付宝、微信字段：

- 实名姓名
- 账号脱敏值
- 收款二维码
- 单笔和日限额

收款二维码只有订单成立后才展示，旧订单二维码不能被新订单复用。

## 10. 商家体系

### 10.1 商家状态

```text
未申请
审核中
待补充材料
待缴保证金
正常营业
暂停接单
保证金不足
风控限制
冻结
清退中
已清退
```

### 10.2 商家申请流程

```text
普通用户
→ 完成账号安全绑定
→ 完成身份认证
→ 提交商家申请
→ 风控/人工审核
→ 缴纳保证金
→ 商家生效
```

复用现有用户、手机号、邮箱和支付密码，不创建商家登录账号。

### 10.3 商家工作台

```text
商家中心
├── 营业状态
├── 待处理订单
├── 今日成交
├── 完成率
├── 广告管理
├── 商家订单
├── 收付款方式
├── 数字资产地址
├── 保证金
├── 评价
└── 商家资料
```

### 10.4 保证金规则

后台支持：

- 固定保证金
- 商家等级保证金
- 风险追加保证金
- 保证金与广告敞口倍数
- 退还冷静期
- 扣罚规则

建议限制：

```text
最大广告敞口 <= 可用保证金 × 后台配置倍数
```

商家被冻结时自动下架广告，进行中订单继续处理或转人工，保证金保持冻结。

## 11. 广告系统

### 11.1 广告方向

商家选择：

- 出售数字资产
- 购买数字资产

从用户视角：

- 用户买币对应商家的出售广告。
- 用户卖币对应商家的购买广告。

### 11.2 广告字段

- 广告编号
- 商家
- 买卖方向
- 数字资产和网络
- 法币
- 固定价格或浮动价格
- 单价或浮动比例
- 可交易数量
- 单笔最小和最大金额
- 总广告额度
- 支付方式
- 付款和放币期限
- 用户认证等级要求
- 用户注册时长要求
- 商家营业时间
- 广告条款
- 自动回复
- 广告状态

### 11.3 发布前校验

- 商家状态正常
- 身份认证有效
- 保证金充足
- 资产或平台余额充足
- 收付款方式有效
- 网络正常
- 未超过广告和并发订单限制
- 风控允许

出售广告发布时冻结数字资产库存。购买广告如果使用平台余额，发布时冻结法币额度；使用外部支付方式时受保证金敞口控制。

## 12. 用户买币流程

```text
钱包 → 买币
→ 选择资产和网络
→ 输入金额或数量
→ 选择商家广告
→ 选择平台余额或外部收币地址
→ 创建订单并锁定价格
→ 冻结商家数字资产
→ 展示商家收款方式
→ 用户付款并标记已付款
→ 商家确认实际到账
→ 平台释放数字资产
→ 完成并评价
```

如果选择平台数字资产余额，使用内部账本即时入账。如果选择外部地址，进入链上广播和确认状态。

付款截图只作为证据，不能作为自动到账依据。没有合规查账能力时，禁止根据截图自动放币。

## 13. 用户卖币流程

```text
钱包 → 卖币
→ 选择资产和网络
→ 输入数量
→ 选择收款位置
→ 系统筛选优质商家
→ 用户确认商家和价格
→ 用户资产进入 OTC 托管
→ 商家付款并标记已付款
→ 用户确认实际到账
→ 平台释放托管资产给商家
→ 完成并评价
```

收款位置：

- 平台法币余额
- 支付宝
- 微信
- 银行卡

订单创建后不能随意更换收款方式。

## 14. 优质商家匹配

先执行硬过滤：

- 商家在线且正常营业
- 保证金和广告余额充足
- 支持同一数字资产和网络
- 支持用户选择的收款方式
- 金额在广告限额内
- 商家未超过并发订单数
- 风控允许双方交易

通过过滤后计算综合评分：

| 指标 | 建议权重 |
| --- | ---: |
| 价格竞争力 | 25% |
| 近 30 天完成率 | 20% |
| 平均付款/放币速度 | 15% |
| 争议率 | 15% |
| 好评率 | 10% |
| 保证金充足率 | 10% |
| 在线状态 | 5% |

客户端显示“推荐商家”和“其他可选商家”，用户可以手动更换，不强制使用第一名。

### 15.4 状态转换规则

每次转换必须校验：

## 16. 托管、冻结与双重账本

所有资金变化必须生成借贷分录，禁止直接修改余额。

用户卖币进入托管示例：

```text
借：用户数字资产可用账户
贷：用户数字资产 OTC 托管账户
```

交易完成：

```text
借：用户数字资产 OTC 托管账户
贷：商家数字资产可用账户
```

保证金扣罚：

```text
借：商家保证金冻结账户
贷：平台赔付准备账户
```

核心要求：

- 每个订单有唯一订单号。
- 每个资金事件有唯一账本流水号。
- 每个操作有唯一幂等键。
- 借贷必须平衡。
- 账本记录禁止物理删除。
- 更正使用反向分录。
- 定期执行法币账本、数字资产账本和链上余额对账。

## 17. 订单超时与取消

后台可设置：

- 用户付款时间
- 商家确认时间
- 用户确认收款时间
- 链上确认等待时间
- 申诉窗口
- 自动取消时间

硬规则：

- 用户标记已付款后订单不能自动取消。
- 标记付款后商家不能自行取消。
- 进入申诉后相关资产保持冻结。
- 支付账户姓名不一致时进入人工审核。
- 恶意标记付款和长期不放币进入风控处罚。

## 20. 商家数据与评价

商家资料展示：

- 累计订单和 30 天订单
- 累计成交额和 30 天成交额
- 完成率
- 平均付款时间
- 平均放币时间
- 好评率
- 争议率
- 商家认证时间
- 保证金保障等级
- 在线状态
- 支持资产、网络和支付方式

保证金金额不直接对普通用户展示，可展示保障等级。

评价规则：

- 只有完成订单可以评价。
- 每方每个订单只能评价一次。
- 支持好评、中评、差评、标签和文字。
- 商家不能删除评价。
- 后台只能隐藏违法内容，不能篡改评分。
- 关联账户互刷评价进入风控。

## 21. 申诉和后台仲裁

### 21.1 证据

- 订单状态时间线
- 订单聊天记录
- 付款截图和账单材料
- 收付款方式快照
- 数字资产地址和 TxID
- 登录设备、IP 和地区
- 风控命中结果
- 操作审计日志

### 21.2 流程

```text
发起申诉
→ 冻结订单和相关资产
→ 双方提交证据
→ 风控初审
→ 仲裁员处理
→ 高金额双人复核
→ 释放资产或退款
→ 必要时扣罚保证金
→ 保存裁决
```

仲裁员不能直接修改余额，只能提交裁决，由账本服务执行资金分录。

## 22. 风控体系

### 22.1 用户风控

- KYC 状态和账户年龄
- 设备数量、同设备多账号
- IP 和地区变化
- 收款姓名一致性
- 高频修改地址和收款方式
- 高频取消订单
- 标记付款但未实际付款
- 高频拆单和异常大额
- 关联账户和异常登录

### 22.2 商家风控

- 完成率和争议率突变
- 收款账户频繁变化
- 多商家共用收款账户
- 保证金不足
- 异常低价广告
- 高频改价
- 并发订单过多
- 设备和 IP 关联

### 22.3 链上风控

- 制裁和黑名单地址
- 诈骗、赌博、混币和被盗资金地址
- 高风险交易所
- 大额快速转移
- 地址风险跳数关联

风险等级：

```text
LOW
MEDIUM
HIGH
BLOCKED
```

高风险地址禁止自动入账或出账，转人工复核。

## 28. 安全红线

- 不允许客户端直接释放资产。
- 不允许通过付款截图自动放币。
- 不允许订单状态逆向覆盖。
- 不允许绕过支付密码授权和风控。
- 不允许直接 UPDATE 用户余额完成仲裁。
- 不允许同一幂等键重复扣款或重复放币。
- 不允许使用浮点数计算资金。
- 不允许广告数量超过已冻结库存。
- 不允许进行中订单使用被修改后的地址或收款方式。
- 不允许普通聊天清除规则删除 OTC 交易证据。
- 不允许商家删除差评或争议记录。

## 30. 第一期建议验收标准

### 30.1 资金正确性

- 任意订单重复请求不会重复冻结、扣款或放币。
- 所有账本借贷平衡。
- 订单取消只解冻本订单资产。
- 仲裁只能通过裁决和账本服务执行。
- 金额精度测试覆盖最小值、最大值和超精度输入。

### 30.2 状态机

- 非法状态转换全部拒绝。
- 双端同时操作只有一个成功。
- 用户标记付款后不能自动取消。
- 申诉状态下资产持续冻结。

### 30.3 实时和缓存

- Gateway 事件只局部更新订单和钱包。
- 清除客户端数据后，登录可恢复服务端订单。
- 旧事件不会覆盖较新的订单状态。
- 空响应不会让订单列表或资产列表闪空。

### 30.4 商家和广告

- 未认证、保证金不足或冻结商家无法发布广告。
- 出售广告数量不超过冻结资产。
- 商家冻结后广告自动下架。
- 推荐商家必须满足全部硬过滤条件。

### 30.5 安全

- 所有 OTC 接口执行现有签名和加密协议。
- 敏感字段不出现在普通日志。
- 高金额释放支持双人复核。
- 权限越权、重放、并发和幂等测试通过。
