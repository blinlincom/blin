# 朋友圈功能接口文档

本文档对应业务端 `/api` 下新增的朋友圈接口。所有接口都必须使用现有安全请求链路：

- 必传公共字段：`appid`、`usertoken`、`device`、`device_flag`、`device_level`、`timestamp`、`nonce`、`client_msg_no`、`sign`。
- 业务字段必须放入 `secure_payload`，使用 `AES-128-CBC` 加密。
- 客户端需要传 `secure_response=1`，服务端成功响应会返回密文 `secure_payload`。
- 媒体文件必须通过 `secure_file` 加密上传，普通 `file` 明文上传不用于朋友圈。

## 数据表

- `mr_moments_post`：朋友圈动态，包含正文、媒体 JSON、可见性、提醒用户、删除状态、审核状态。
- `mr_moments_like`：点赞记录，`appid + post_id + user_id` 唯一。
- `mr_moments_comment`：评论记录，支持回复某条评论，也包含审核状态。

迁移文件：`/www/wwwroot/blin/database_moments_migration.sql`。

## 审核机制

后台入口：`聊天管理 -> 朋友圈管理`，审核配置入口：`聊天管理 -> 朋友圈审核设置`。

- `audit_mode=0`：关闭审核，发布后直接通过。
- `audit_mode=1`：机审，按 `public/prohibited_word.txt` 敏感词检测，可配置命中后自动驳回或只记录说明。
- `audit_mode=2`：人工审核，发布后进入待审核，非作者用户不可见。

动态和评论都会返回审核字段：

- `review_status`：`0` 待审核，`1` 审核通过，`2` 审核拒绝。
- `review_status_name`：审核状态文案。
- `review_mode`：`off` 关闭审核，`machine` 机审，`manual` 人工审核。
- `review_reason`：审核说明。

可见规则：

- 作者始终可以看到自己的动态和审核状态。
- 非作者只能看到 `review_status=1` 且符合可见性规则的动态。
- 待审核或审核拒绝的动态不会进入好友的信息流。
- 评论发布也走同一套审核策略；非评论作者只能看到审核通过的评论。

## 可见性

- `visibility=0`：好友可见。
- `visibility=1`：仅自己可见。
- `visibility=2`：部分好友可见，使用 `visible_user_ids`。

服务端会校验部分可见用户和提醒用户必须是当前用户的好友。

## 接口

### 朋友圈信息流

`POST /api/moments_feed`

业务参数：

```json
{
  "page": "1",
  "limit": "20"
}
```

返回：

```json
{
  "list": [],
  "pagecount": 1,
  "current_number": 1
}
```

只返回自己和好友的可见动态。

### 指定用户朋友圈

`POST /api/moments_user`

业务参数：

```json
{
  "user_id": "2",
  "page": "1",
  "limit": "20"
}
```

非好友只能返回空列表。

### 朋友圈详情

`POST /api/moments_detail`

业务参数：

```json
{
  "post_id": "1"
}
```

### 媒体上传

`POST /api/moments_media_upload`

业务参数放入 `secure_payload`：

```json
{
  "media_type": "image",
  "name": "photo.jpg",
  "mime": "image/jpeg",
  "size": "102400",
  "width": "1080",
  "height": "1440",
  "duration": "0"
}
```

文件字段：`secure_file`。

返回：

```json
{
  "media": {
    "type": "image",
    "url": "/uploads/chat/20260706/xxx.jpg",
    "thumb_url": "",
    "name": "photo.jpg",
    "mime": "image/jpeg",
    "size": 102400,
    "width": 1080,
    "height": 1440,
    "duration": 0
  }
}
```

### 发布朋友圈

`POST /api/moments_publish`

业务参数：

```json
{
  "content": "今天很好",
  "media": "[{\"type\":\"image\",\"url\":\"/uploads/chat/20260706/xxx.jpg\"}]",
  "visibility": "0",
  "visible_user_ids": [2, 3],
  "remind_user_ids": [2],
  "location": "深圳"
}
```

正文和媒体不能同时为空。最多 9 个媒体。

返回动态会包含审核字段。人工审核模式下接口成功但消息为 `已提交审核`，客户端应在发布完成后展示待审核状态；机审拒绝时消息为 `发布未通过审核`，动态仅作者可见并带有拒绝原因。

### 删除朋友圈

`POST /api/moments_delete`

业务参数：

```json
{
  "post_id": "1"
}
```

仅发布者可删除。

### 点赞

`POST /api/moments_like`

业务参数：

```json
{
  "post_id": "1"
}
```

### 取消点赞

`POST /api/moments_unlike`

业务参数：

```json
{
  "post_id": "1"
}
```

### 发表评论

`POST /api/moments_comment_add`

业务参数：

```json
{
  "post_id": "1",
  "content": "不错",
  "reply_comment_id": "0",
  "reply_user_id": "0"
}
```

`reply_comment_id` 大于 0 时，服务端会按该评论自动确定回复用户。

返回评论会包含审核字段。人工审核模式下消息为 `评论已提交审核`；机审拒绝时消息为 `评论未通过审核`，该评论只会对评论作者自己可见。

### 删除评论

`POST /api/moments_comment_delete`

业务参数：

```json
{
  "comment_id": "1"
}
```

评论发布者和动态发布者可以删除。

## 客户端交互

- 发现页和我的页的“朋友圈”入口进入真实朋友圈。
- 信息流优先读取加密 MMKV 缓存，再请求服务端刷新，减少白屏和闪屏。
- 发布页支持文字、图片、视频；图片最多 9 张，视频单独发布。
- 发布时先逐个上传媒体，上传成功后再发布动态。
- 点赞、评论、删除成功后，当前动态局部刷新，不整页跳动。
- 发布后按 `review_status` 显示审核状态：待审核、审核拒绝只在作者自己的朋友圈中展示，不进入好友信息流。
