# BIM 好友二维码与外部唤起

## 功能范围

本功能用于“我的二维码”和“扫一扫添加好友”。

- 用户在“我的”页面点击“我的二维码”，生成自己的好友二维码。
- App 内用户点击“扫一扫”，扫描好友二维码后进入好友查询页。
- 外部扫码工具扫描二维码后，通过 `bim://friend/add?username=用户名` 唤起 BIM。
- 如果用户未登录，App 会先停留在登录页；登录成功后继续打开该好友查询页。
- 查询好友只调用现有业务端 `im_friend_search`，按用户名查询，不暴露 IMUID。

## 二维码内容

当前二维码默认内容：

```text
bim://friend/add?username={username}
```

客户端同时支持解析下面的 HTTPS 形式，方便后期配置 Android App Links / iOS Universal Links：

```text
https://blcold.cn/app/friend?username={username}
```

## 平台配置

Android 已在 `android/app/src/main/AndroidManifest.xml` 配置：

- `bim://friend/...`
- `https://blcold.cn/app/friend...`
- `flutter_deeplinking_enabled=false`，由 `app_links` 接管深链。

iOS 已在 `ios/Runner/Info.plist` 配置：

- URL Scheme：`bim`
- `FlutterDeepLinkingEnabled=false`

macOS 已在 `macos/Runner/Info.plist` 配置：

- URL Scheme：`bim`

Windows 已在 `windows/runner/main.cpp` 接入 `SendAppLinkToInstance()`：

- 外部协议再次打开 App 时，会把链接转发给已运行实例。
- 正式安装包仍需要安装器写入 Windows URL Protocol 注册表项，把 `bim://` 交给 BIM 可执行文件。

Linux 已在 `linux/runner/my_application.cc` 调整为单实例命令行处理模式：

- 外部协议通过命令行传入时，已运行实例可以收到链接。
- 正式发布仍需要 `.desktop` 文件声明 `MimeType=x-scheme-handler/bim;`。

如果要让 iOS 系统相机直接识别 HTTPS 并打开 App，需要服务端补充 Apple Universal Links 的 `apple-app-site-association` 文件和 Xcode Associated Domains。当前二维码使用 `bim://`，不依赖该文件。

## 测试命令

Android 调试机可执行：

```bash
adb shell am start -a android.intent.action.VIEW -d "bim://friend/add?username=testuser"
```

HTTPS 兼容路径可执行：

```bash
adb shell am start -a android.intent.action.VIEW -d "https://blcold.cn/app/friend?username=testuser"
```

预期结果：

- 已登录：直接进入“添加好友”查询结果页。
- 未登录：先显示登录页，登录成功后进入查询结果页。
- 用户已是好友：按钮显示“发消息”。
- 已发申请：按钮显示“已申请”。
- 对方已申请我：按钮显示“待处理”，点击进入新的朋友。
- 非好友：按钮显示“添加”，点击发送好友申请。

## 业务规则

- 二维码只携带 `username`。
- 扫码后必须通过 `im_friend_search` 查询真实用户状态。
- 添加好友仍调用现有 `im_friend_apply`。
- 不使用 IMUID、全局 ID 或设备 ID 作为用户可见标识。
- 无效二维码不会发起业务请求。
