# BIM 后台保活与离线同步方案

## 目标

本方案不接入手机厂商推送，客户端通过 Gateway 长连接、Android 前台服务、离线 cursor 补偿同步来提高后台消息到达率。

需要明确：不用厂商推送不能保证所有系统、所有省电策略下都 100% 后台实时。企业级目标是：

- 前台消息实时。
- Android 后台尽量保持 Gateway 长连接。
- 断线、杀进程、换网络后不丢消息。
- 下次打开 App 后按 cursor 和服务端历史补齐。
- 在线状态以 Gateway 心跳和服务端 presence 为准，不做假在线。

## Android

客户端新增 `BackgroundReceiveService` 前台服务：

- 登录成功后默认开启。
- 退出登录后自动停止。
- 用户可以在“我的 -> 设置 -> 消息连接 -> 后台消息接收”关闭。
- 前台服务只做系统合规保活，不复制 IM 业务逻辑。
- 真正的消息收发仍由 Flutter 侧 Gateway 连接管理器执行。

Android 权限：

- `FOREGROUND_SERVICE`
- `FOREGROUND_SERVICE_DATA_SYNC`
- `POST_NOTIFICATIONS`
- `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`

如果通知权限未开启或电池优化未放行，设置页会展示风险并提供系统设置跳转。

## iOS

iOS 不做伪后台长连接。当前策略：

- 前台保持 Gateway 实时连接。
- 进入后台时申请短后台任务，用于完成 ACK 和收尾。
- 长时间后台或被系统杀死后，不承诺实时。
- 重新打开 App 后通过 Gateway cursor 和历史同步补齐消息。

音视频来电如果后续要做到系统级可靠提醒，需要单独接 APNs/PushKit + CallKit，不能用 PushKit 推普通聊天消息。

## Gateway 连接生命周期

客户端连接状态：

- `连接中...`
- `重连中...`
- `同步中...`
- `已连接`
- `未连接`

后台接收保护开启时：

- App 进入后台不主动关闭 Gateway。
- Gateway 断开后继续指数退避重连。
- 前台服务通知同步显示当前连接状态。

后台接收保护关闭时：

- App 后台后停止后台重连。
- 再次进入前台时恢复连接并同步离线消息。

## 离线补偿同步

Gateway 下发消息带 cursor，客户端 ACK 成功后写入本地 cursor。

连接成功后客户端执行：

1. 使用本地最后 ACK cursor 打开 Gateway 流。
2. Gateway 从 cursor 后继续推送缺失帧。
3. 客户端本地落盘后 ACK。
4. 同步服务端会话列表。
5. 对最近会话触发历史窗口校正，避免会话列表有消息但聊天页缺消息。

相关日志：

- `gateway stream connect start`
- `gateway stream connected`
- `gateway heartbeat timeout`
- `gateway reconnect scheduled`
- `gateway ack batch committed`
- `offline sync start`
- `offline sync done`
- `offline sync failed`
- `background receive guard started`
- `background receive status refreshed`

## 用户侧入口

路径：

`我的 -> 设置 -> 消息连接 -> 后台消息接收`

页面展示：

- 后台接收保护开关。
- 当前连接状态。
- 通知权限。
- 电池优化。
- 后台服务状态。

## 测试建议

Android：

1. 登录账号 A、B。
2. A 前台，B 后台，A 给 B 发文字、图片、红包、转账。
3. B 不杀进程等待消息到达。
4. B 杀进程后重新打开，检查离线消息是否补齐。
5. 关闭通知权限，检查设置页提示。
6. 开启省电限制，检查设置页提示。
7. 关闭“后台接收保护”，确认后台断线后前台恢复同步。

iOS：

1. 前台实时收发。
2. 短时间后台后回前台，确认 ACK 和同步正常。
3. 长时间后台或杀进程后打开，确认历史补偿同步正常。

## 边界

不用厂商推送时，后台实时率取决于系统策略、通知权限、电池优化和网络状态。系统杀死进程后，任何自建长连接都会断开，客户端只能在下次启动后补偿同步。
