# TRON 链上钱包完整配置与运营手册

## 1. 已实现的资金链路

系统已经实现以下完整流程：

1. 为每个用户按固定 HD 路径生成独立 TRC20 地址。
2. 扫描已确认的 USDT 充值事件，按 `txid + log_index` 幂等入账。
3. 达到最低归集数量后生成归集任务。
4. 资源钱包只补足用户地址缺少的 TRX，不会在每次重试时重复补固定金额。
5. 用户地址本地签名，向平台归集钱包广播 USDT 转账。
6. 广播结果不确定时保存预先计算的 `txid` 并继续确认，不重新发送另一笔交易。
7. 提币先冻结用户数字资产，后台审核通过后进入链上执行队列。
8. 链上成功后扣除冻结资产；链上明确失败后幂等退回可用余额。
9. 后台可查看地址、充值流水、数字资产流水、提现审核、归集订单和失败原因。

## 2. 钱包分工

- **用户充值地址**：每个用户一个，由主种子派生，只接收充值。
- **资源钱包**：只持有 TRX，为用户充值地址提供归集手续费资源。
- **归集钱包**：接收用户地址归集后的 USDT，可使用冷钱包或受控热钱包地址。
- **提现热钱包**：持有运营所需 USDT 和 TRX/Energy，专门执行用户提币。

生产环境不要把四种职责混成同一个私钥。资源钱包和提现热钱包应设置余额告警及人工补充上限。

## 3. 配置文件

服务器配置文件：

```text
/etc/bim/tron-wallet.env
```

参考内容：

```dotenv
TRON_WALLET_LISTEN=127.0.0.1:9088
TRON_INTERNAL_SECRET=至少32位随机字符串
TRON_MASTER_SEED_HEX=离线生成并备份的主种子
TRON_FULLNODE_URL=https://api.trongrid.io
TRON_EVENT_API_URL=https://api.trongrid.io
TRON_API_KEY=TronGrid免费APIKey
TRON_CALLBACK_URL=https://你的业务域名/callback

# 未完成小额验收前必须关闭
TRON_CHAIN_WORKER_ENABLED=false
TRON_WORKER_ID=wallet-1

# 64位十六进制私钥，不要填地址
TRON_RESOURCE_PRIVATE_KEY=
TRON_RESOURCE_TOPUP_SUN=30000000
TRON_WITHDRAW_HOT_PRIVATE_KEY=
```

配置文件权限：

```bash
chown root:root /etc/bim/tron-wallet.env
chmod 600 /etc/bim/tron-wallet.env
```

## 4. 后台配置顺序

1. 数字钱包 -> 链上配置：填写 USDT TRC20 合约地址、最低充值、最低提币、手续费和每日限额。
2. 数字钱包 -> 自动归集：填写归集钱包地址、资源钱包地址和最低归集数量。
3. 保持自动归集关闭，先重启钱包服务并检查健康状态。
4. 给专用测试用户充值小额 USDT，确认充值流水与数字资产流水一致。
5. 给资源钱包准备少量 TRX，给提现热钱包准备少量 USDT 和 TRX。
6. 将 `TRON_CHAIN_WORKER_ENABLED` 改为 `true`，重启服务。
7. 后台开启自动归集，只进行一笔小额归集测试。
8. 创建一笔小额提币，后台审核通过，核对 TXID、到账金额、冻结扣除和流水。
9. 验收完成后再按运营限额补充热钱包资金。

## 5. 健康检查

在服务器执行：

```bash
curl -s http://127.0.0.1:9088/health
```

重点字段：

- `address_derivation_enabled`：主种子是否配置。
- `chain_worker_enabled`：链上执行任务是否开启。
- `resource_wallet_configured`：资源钱包私钥是否配置。
- `withdraw_wallet_configured`：提现热钱包私钥是否配置。
- `resource_address`：服务从资源私钥计算出的地址，必须与后台填写地址一致。
- `withdraw_address`：提现热钱包地址。

## 6. 归集与提现安全规则

1. 未配置资源钱包、归集地址或执行开关时，后台禁止开启自动归集。
2. 提现必须经过后台审核，审核前资产保持冻结。
3. 已产生 `txid` 的任务只进入确认流程，不允许自动重新构造交易。
4. 广播明确失败且没有 `txid` 才允许指数退避重试，最多五次后转人工处理。
5. 已广播但长时间未确认的订单禁止直接退款，应先用区块浏览器核对 TXID。
6. 所有用户余额变化必须有总账和分录，禁止直接改数据库余额。
7. 运营后台不得显示任何主种子或私钥。

## 7. 监控建议

- 钱包服务不可用持续 1 分钟告警。
- 资源钱包 TRX 低于运营阈值告警。
- 提现热钱包 USDT 小于待审核及排队提现总额时告警并暂停审核。
- `manual_review`、`failed_refunded` 或归集失败订单立即告警。
- 每日核对：用户数字资产负债总额、提现冻结额、归集钱包余额、提现热钱包余额、用户地址未归集余额。
