# BIM 服务号功能说明

## 功能范围

服务号用于承载系统通知、支付通知和后续可配置服务入口。客户端面向普通用户，只展示服务号名称、头像、简介、免打扰和置顶等用户可理解的信息，不展示 `service_id`、`user_id`、`channel_id`、`code` 等后台字段。

当前已落地：

- 后台服务号管理：`/service_account/index`
- 后台服务号菜单管理：服务号列表点击“菜单”
- 客户端联系人页入口：联系人 -> 服务号
- 客户端服务号会话页：从服务号列表或会话列表进入
- 客户端服务号设置：右上角设置，可设置免打扰、置顶；后台允许时可取消关注
- 默认支付服务号：`支付通知`，默认菜单为 `我的账单`、`支付服务`、`收付款`

## 数据表

服务端已新增三张表：

- `mr_service_account`：服务号主体配置
- `mr_service_account_menu`：服务号底部菜单配置
- `mr_service_account_user`：用户维度的免打扰、置顶、关注状态

默认会基于钱包通知账号创建 `payment_service` 服务号。若钱包通知账号不存在，客户端首次请求服务号接口时，业务端会通过已有钱包通知服务创建默认账号并补齐服务号配置。

## 后台配置

进入后台后，在左侧 `聊天管理 -> 服务号管理`：

1. 新增服务号时必须选择 `AppID`、绑定用户 ID、服务号标识和服务号名称。
2. 服务号标识只允许字母、数字和下划线，同一个 AppID 下不能重复。
3. `联系人展示` 控制客户端联系人页服务号列表是否展示。
4. `会话展示` 预留给会话侧展示控制。
5. `菜单模式` 当前客户端支持 `菜单` 和 `无底部栏`。
6. 菜单动作支持：
   - `wallet_home`：钱包首页
   - `wallet_bills`：我的账单
   - `wallet_pay_receive`：收付款
   - `scan`：扫一扫
   - `url`、`page`：已保留，客户端当前不直接打开，避免跳转安全漏洞

## 客户端接口

客户端调用都走已有 `secureSignedImPost`，请求带设备、时间戳、签名，并要求加密响应。

### 服务号列表

接口：`service_account_list`

请求参数：无业务参数

返回重点字段：

- `service_id`：服务号 ID
- `name`：服务号名称
- `avatar`：头像
- `description`：简介
- `channel_id`：服务号会话 channel
- `channel_type`：悟空单聊 channel 类型
- `muted`：当前用户是否免打扰
- `pinned`：当前用户是否置顶
- `following`：当前用户是否关注
- `menus`：底部菜单

### 服务号详情

接口：`service_account_detail`

请求参数：

- `service_id`：服务号 ID

用途：进入服务号会话时同步最新菜单和设置。

### 更新服务号设置

接口：`service_account_settings_update`

请求参数：

- `service_id`：服务号 ID
- `muted`：可选，`1` 免打扰，`0` 关闭免打扰
- `pinned`：可选，`1` 置顶，`0` 取消置顶
- `following`：可选，`0` 取消关注。只有后台允许取消关注时可用

## 客户端缓存

客户端会把服务号列表写入 MMKV 加密缓存：

- 首屏先显示本地缓存，避免联系人页闪白。
- 网络刷新成功后覆盖本地缓存。
- 用户更新免打扰或置顶后立即合并到本地缓存。

## 安全规则

- 服务号列表和设置接口必须登录后调用。
- 设置接口必须走安全请求，不接受普通明文参数作为正式入口。
- 用户只能修改自己在 `mr_service_account_user` 里的设置。
- 客户端不执行未知菜单动作，避免后台误配 URL 或页面标识带来跳转风险。
- 服务号绑定用户必须属于同一个 AppID。
