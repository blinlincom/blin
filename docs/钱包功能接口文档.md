# BIM 钱包功能接口文档

## 功能范围

本次钱包只展示余额，不展示积分。客户端入口在“我的 - 钱包”，包含余额、收付款、充值、提现、账单、支付密码、提现记录。

后台新增“钱包管理”，包含：

- 收付款订单：`wallet/index`
- 余额流水：`wallet/bills`

## 金额规则

- 钱包余额支持小数点后两位。
- 服务端金额字段使用 `DECIMAL(18,2)`。
- 客户端金额统一按字符串处理，例如 `1.23`，不按整数或浮点金额传递。
- 金额必须大于 `0.00`。
- 服务端拒绝超过两位小数，例如 `1.234` 会返回“金额格式不正确，最多支持小数点后两位”。

## 安全规则

钱包接口属于敏感业务，必须使用 IM 安全请求规则：

- 请求必须带 `device`、`device_flag`、`device_level`、`timestamp`、`nonce`、`client_msg_no`、`sign`。
- 钱包业务字段必须放进 `secure_payload`。
- 响应必须传 `secure_response=1`，成功数据会用 `secure_payload` 加密返回。
- 明文提交 `amount`、`money`、`pay_password`、`account`、`name`、`qr_token`、`order_no`、`payee_username` 等字段会被服务端拒绝。

## 接口列表

所有接口路径均为：

```text
POST https://blcold.cn/api/{action}
```

### 查询余额

`wallet_balance`

请求 `secure_payload`：

```json
{}
```

响应解密后：

```json
{
  "user_id": 900100015,
  "balance": "36.00",
  "balance_label": "36.00",
  "pay_password_set": 1,
  "server_time": 1783514188
}
```

### 设置支付密码

`wallet_pay_password_set`

请求 `secure_payload`：

```json
{
  "new_pay_password": "123456"
}
```

规则：支付密码必须是 6 位数字，服务端只保存盐值哈希，不保存明文。

### 查询账单

`wallet_bill_list`

请求 `secure_payload`：

```json
{
  "scene": "all",
  "page": "1",
  "limit": "20"
}
```

`scene` 可选值：

- `all`：全部
- `income`：收入
- `expense`：支出
- `withdraw`：提现
- `charge`：卡密充值
- `im`：聊天红包/转账
- `scan`：扫码收付款

### 卡密充值

`wallet_recharge_km`

请求 `secure_payload`：

```json
{
  "km": "卡密"
}
```

### 提现

`wallet_withdraw`

请求 `secure_payload`：

```json
{
  "money": "10.50",
  "type": "0",
  "account": "收款账户",
  "name": "收款人姓名",
  "remark": "选填备注"
}
```

说明：

- `type=0` 表示余额提现。
- 客户端钱包不展示积分提现。
- 服务端在事务中锁定用户余额并原子扣减。

### 提现记录

`wallet_withdraw_list`

请求 `secure_payload`：

```json
{
  "page": "1",
  "limit": "20"
}
```

### 生成收款码

`wallet_collect_code_create`

请求 `secure_payload`：

```json
{
  "amount": "1.23",
  "remark": "选填备注"
}
```

说明：

- 由收款方生成。
- 付款方扫码后需要输入自己的支付密码。
- 不能扫描自己的收款码。

### 生成付款码

`wallet_pay_code_create`

请求 `secure_payload`：

```json
{
  "payee_username": "收款方用户名",
  "amount": "1.23",
  "pay_password": "123456",
  "remark": "选填备注"
}
```

说明：

- 由付款方生成。
- 生成前必须验证付款方支付密码。
- 二维码只能被指定 `payee_username` 对应的收款方消费一次。
- 收款方扫码确认收款，不需要输入收款方支付密码。

### 扫码预览订单

`wallet_qr_scan`

请求 `secure_payload`：

```json
{
  "qr_token": "二维码token"
}
```

说明：

- 二维码内容是 `bim://wallet/pay?token=...`。
- 服务端只存 `qr_token_hash`，不明文落库 token。

### 确认扫码收付款

`wallet_qr_pay_confirm`

收款码付款请求：

```json
{
  "qr_token": "二维码token",
  "pay_password": "123456"
}
```

付款码收款请求：

```json
{
  "qr_token": "二维码token"
}
```

说明：

- 收款码：扫码用户是付款方，必须输入支付密码。
- 付款码：扫码用户是指定收款方，服务端直接扣付款方余额并入账给收款方。
- 订单会锁行处理，已支付、取消、过期订单不能重复消费。

### 查询订单状态

`wallet_order_status`

请求 `secure_payload`：

```json
{
  "order_no": "WC202607082037064912CDF06353"
}
```

## 数据表

新增表：

- `mr_wallet_pay_password`：支付密码盐值和哈希。
- `mr_wallet_order`：扫码收付款订单。

已调整字段：

- `mr_user.money`：`DECIMAL(18,2)`
- `mr_km.money`：`DECIMAL(18,2)`
- `mr_wallet_order.amount`：`DECIMAL(18,2)`
- `mr_withdrawal_record.withdraw_fee`：`DECIMAL(18,2)`

## 已验证

- `wallet_balance` 成功响应为密文，原始响应不包含余额明文。
- 解密后余额保留两位小数，例如 `36.00`。
- 明文提交 `amount=1.23` 会被拒绝。
- `wallet_collect_code_create` 接受 `1.23`。
- `wallet_collect_code_create` 拒绝 `1.234`。
