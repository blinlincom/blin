# BIM 钱包功能接口文档

## 功能范围

本次钱包只展示余额，不展示积分。客户端入口在“我的 - 钱包”，包含余额、收付款、充值、提现、账单、支付密码、提现记录。

后台新增“钱包管理”，包含：

- 收付款订单：`wallet/index`
- 余额流水：`wallet/bills`

## 金额规则

- 钱包余额支持小数点后两位。
- 服务端金额字段使用 `DECIMAL(18,2)`。
- 客户端金额统一按字符串处理，例如 `1.23`，不按整数或浮点金额传递。
- 收款码和付款码创建阶段允许金额为空，表示扫码确认时再输入金额。
- 扣款确认阶段金额必须大于 `0.00`。
- 服务端拒绝超过两位小数，例如 `1.234` 会返回“金额格式不正确，最多支持小数点后两位”。

## 安全规则

钱包接口属于敏感业务，必须使用 IM 安全请求规则：

- 请求必须带 `device`、`device_flag`、`device_level`、`timestamp`、`nonce`、`client_msg_no`、`sign`。
- 钱包业务字段必须放进 `secure_payload`。
- 响应必须传 `secure_response=1`，成功数据会用 `secure_payload` 加密返回。
- 明文提交 `amount`、`money`、`pay_password`、`account`、`name`、`qr_token`、`order_no`、`request_id` 等字段会被服务端拒绝。
- `wallet_qr_pay_confirm` 必须提交客户端唯一 `request_id`，格式为 `8-64` 位字母、数字、下划线或中划线，用于幂等防重扣。

## 接口列表

所有接口路径均为：

```text
POST https://blcold.cn/api/{action}
```

### 查询余额

`wallet_balance`

请求 `secure_payload`：

```json
{}
```

响应解密后：

```json
{
  "user_id": 900100015,
  "balance": "36.00",
  "balance_label": "36.00",
  "pay_password_set": 1,
  "server_time": 1783514188
}
```

### 设置支付密码

`wallet_pay_password_set`

请求 `secure_payload`：

```json
{
  "new_pay_password": "123456"
}
```

规则：支付密码必须是 6 位数字，服务端只保存盐值哈希，不保存明文。

### 查询账单

`wallet_bill_list`

请求 `secure_payload`：

```json
{
  "scene": "all",
  "page": "1",
  "limit": "20"
}
```

`scene` 可选值：

- `all`：全部
- `income`：收入
- `expense`：支出
- `withdraw`：提现
- `charge`：卡密充值
- `im`：聊天红包/转账
- `scan`：扫码收付款

响应解密后每条账单统一字段：

```json
{
  "id": 179,
  "bill_no": "BILL179",
  "order_no": "TR202607082336402E058EAE95F84457",
  "scene": "9",
  "scene_name": "红包/转账",
  "direction": "expense",
  "direction_name": "支出",
  "amount": "1.00",
  "amount_label": "-¥1.00",
  "target_name": "Artisan",
  "target_avatar": "",
  "status": 1,
  "status_name": "交易成功",
  "remark": "转账给Artisan，交易单号：TR202607082336402E058EAE95F84457，待收款，手续费：0.00",
  "created_at": "2026-07-08 23:36:40"
}
```

### 账单详情

`wallet_bill_detail`

请求 `secure_payload`：

```json
{
  "id": "179"
}
```

说明：

- 只能查看自己的账单。
- 如果账单备注中带订单号或交易单号，服务端会尝试关联钱包订单并返回 `order`。
- 客户端点击账单列表项后调用此接口展示详情。

### 卡密充值

`wallet_recharge_km`

请求 `secure_payload`：

```json
{
  "km": "卡密"
}
```

### 提现

`wallet_withdraw`

请求 `secure_payload`：

```json
{
  "money": "10.50",
  "type": "0",
  "account": "收款账户",
  "name": "收款人姓名",
  "remark": "选填备注"
}
```

说明：

- `type=0` 表示余额提现。
- 客户端钱包不展示积分提现。
- 服务端在事务中锁定用户余额并原子扣减。

### 提现记录

`wallet_withdraw_list`

请求 `secure_payload`：

```json
{
  "page": "1",
  "limit": "20"
}
```

### 当前收款码

`wallet_collect_code_current`

请求 `secure_payload`：

```json
{}
```

设置固定金额时：

```json
{
  "amount": "1.23",
  "remark": "选填备注"
}
```

说明：

- 客户端进入收款码页面自动调用。
- `amount` 不传时生成非固定金额收款码，付款方扫码后输入金额。
- `amount` 传入时生成固定金额收款码。
- 付款方扫码后需要输入自己的支付密码。
- 不能扫描自己的收款码。
- 服务端只存 `qr_token_hash`，不明文落库 token。
- 兼容方法：`wallet_collect_code_create`、`wallet_collect_code_update` 内部执行同一逻辑。

### 当前付款码

`wallet_pay_code_current`

请求 `secure_payload`：

```json
{
  "pay_password": "123456"
}
```

说明：

- 客户端进入付款码页面后输入一次支付密码，之后页面内按过期时间自动刷新。
- 不再提前填写收款方和金额。
- 二维码短时有效，只能消费一次。
- 任意非本人用户扫码后输入收款金额并确认收款。
- 服务端确认时扣付款方余额并给扫码方入账。
- 兼容方法：`wallet_pay_code_create` 内部执行同一逻辑。

### 扫码预览订单

`wallet_qr_scan`

请求 `secure_payload`：

```json
{
  "qr_token": "二维码token"
}
```

说明：

- 收款码内容是 `bim://wallet/collect?token=...`。
- 付款码内容是 `bim://wallet/pay?token=...`。
- 服务端只存 `qr_token_hash`，不明文落库 token。

### 确认扫码收付款

`wallet_qr_pay_confirm`

收款码付款请求：

```json
{
  "qr_token": "二维码token",
  "amount": "1.23",
  "pay_password": "123456",
  "request_id": "wallet_1783514188123456_a1b2c3d4"
}
```

付款码收款请求：

```json
{
  "qr_token": "二维码token",
  "amount": "1.23",
  "request_id": "wallet_1783514188123456_a1b2c3d4"
}
```

说明：

- 收款码：扫码用户是付款方，必须输入支付密码；如果收款码已固定金额，服务端以订单金额为准。
- 付款码：扫码用户是收款方，必须输入收款金额；服务端直接扣付款方余额并入账给扫码方。
- 订单会锁行处理，已支付、取消、过期订单不能重复消费。
- 同一订单同一 `request_id` 重试会返回同一结果，不会重复扣款。

### 查询订单状态

`wallet_order_status`

请求 `secure_payload`：

```json
{
  "order_no": "WC202607082037064912CDF06353"
}
```

## 数据表

新增表：

- `mr_wallet_pay_password`：支付密码盐值和哈希。
- `mr_wallet_order`：扫码收付款订单。

已调整字段：

- `mr_user.money`：`DECIMAL(18,2)`
- `mr_km.money`：`DECIMAL(18,2)`
- `mr_wallet_order.amount`：`DECIMAL(18,2)`
- `mr_wallet_order.payee_id`：`BIGINT NOT NULL DEFAULT 0`，支持动态付款码扫码后再写入收款方。
- `mr_wallet_order.confirm_request_id`：确认支付幂等号。
- `mr_withdrawal_record.withdraw_fee`：`DECIMAL(18,2)`


迁移后需要确认字段：

```sql
SHOW COLUMNS FROM mr_user LIKE 'money';
SHOW COLUMNS FROM mr_km LIKE 'money';
SHOW COLUMNS FROM mr_withdrawal_record LIKE 'withdraw_fee';
SHOW COLUMNS FROM mr_wallet_order LIKE 'amount';
SHOW COLUMNS FROM mr_wallet_order LIKE 'payee_id';
SHOW COLUMNS FROM mr_wallet_order LIKE 'confirm_request_id';
```

金额字段应为 `decimal(18,2)`，`payee_id` 默认值应为 `0`，`confirm_request_id` 应存在。

## 已验证

- `wallet_balance` 成功响应为密文，原始响应不包含余额明文。
- 解密后余额保留两位小数，例如 `36.00`。
- 明文提交 `amount=1.23` 会被拒绝。
- `wallet_collect_code_current` 不传金额可自动生成收款码。
- `wallet_collect_code_current` 接受 `1.23`。
- `wallet_collect_code_current` 拒绝 `1.234`。
- `wallet_pay_code_current` 不再要求收款方和金额。
- `wallet_bill_list` 返回标准 `amount` 和 `amount_label`，不再由客户端猜金额。
- `wallet_bill_detail` 可查看账单详情。
- 测试创建的收款码订单已取消，没有留下待支付测试订单。
