# BIM 钱包功能接口文档

## 功能范围

本次钱包只展示余额，不展示积分。客户端入口在“我的 - 钱包”，包含余额、收付款、充值、提现、账单、支付密码、提现记录。

后台新增“钱包管理”，包含：

- 收付款订单：`wallet/index`
- 余额流水：`wallet/bills`
- 支付密码：`wallet/pay_passwords`，支持重置为空和解锁。

## 金额规则

- 钱包余额支持小数点后两位。
- 服务端金额字段使用 `DECIMAL(18,2)`。
- 客户端金额统一按字符串处理，例如 `1.23`，不按整数或浮点金额传递。
- 收款码和付款码创建阶段允许金额为空，表示扫码确认时再输入金额。
- 扣款确认阶段金额必须大于 `0.00`。
- 服务端拒绝超过两位小数，例如 `1.234` 会返回“金额格式不正确，最多支持小数点后两位”。

## 安全规则

钱包接口属于敏感业务，必须使用 IM 安全请求规则：

- 请求必须带 `device`、`device_flag`、`device_level`、`timestamp`、`nonce`、`client_msg_no`、`sign`。
- 钱包业务字段必须放进 `secure_payload`。
- 响应必须传 `secure_response=1`，成功数据会用 `secure_payload` 加密返回。
- 明文提交 `amount`、`money`、`pay_password`、`account`、`name`、`qr_token`、`order_no`、`request_id` 等字段会被服务端拒绝。
- `wallet_qr_pay_confirm` 必须提交客户端唯一 `request_id`，格式为 `8-64` 位字母、数字、下划线或中划线，用于幂等防重扣。
- 红包和转账必须提交 `pay_password`，服务端在扣款前校验。
- 支付密码输错 3 次后锁定，只能由后台解锁。
- 手机号、邮箱、安全验证码发送前必须先通过图片验证码。客户端不能在未通过图片验证码时直接请求短信或邮箱验证码。

## 钱包服务号

扫码付款、扫码收款成功后，系统会通过独立服务号通知用户，不会把收款和支付信息发到好友私聊里。

服务号规则：

- 服务端自动创建系统用户 `__wallet_service_{appid}`，用户端展示名称为“支付通知”。
- 通知消息使用 `content_type=wallet_notice`，底层消息类型默认 `5401`。
- 服务号只用于通知，客户端打开该会话后输入框禁用，不能给服务号发文字、图片、红包、转账或通话。
- 服务号不写入好友关系，不出现在联系人好友列表。
- 付款方收到 `[付款]付款成功` 类摘要，收款方收到 `[收款]收款到账` 类摘要。
- 会话列表的 `[付款]` 使用转账橙色，`[收款]` 使用主色，摘要不展示内部订单明细。
- 详情卡片展示标题、金额、订单号和支付时间，用户查看账单详情仍走 `wallet_bill_detail`。

### 发送支付密码验证码

`wallet_security_code_send`

请求 `secure_payload`：

```json
{
  "verification_method": "mobile",
  "captcha": "图片验证码"
}
```

响应解密后：

```json
{
  "method": "mobile",
  "target": "138****8888",
  "expire_in": 300,
  "security_methods": []
}
```

规则：

- `verification_method` 可选 `mobile` 或 `email`。
- 只能发送到当前登录用户已绑定的手机号或邮箱。
- 用户没有绑定手机号、邮箱或其他安全验证方式时，服务端拒绝设置支付密码。
- `captcha` 必填，对应 `get_image_verification_code` 的 `type=3`。
- 验证码发送成功或失败后，客户端都要刷新图片验证码，避免重复使用旧图形码。

### 绑定手机号

发送验证码：

`user_mobile_bind_code_send`

```json
{
  "mobile": "13800138000",
  "captcha": "图片验证码"
}
```

确认绑定：

`user_mobile_bind_confirm`

```json
{
  "mobile": "13800138000",
  "verify_code": "123456"
}
```

规则：

- 图片验证码使用 `get_image_verification_code?type=3`。
- 手机验证码只发送到本次要绑定的手机号。
- 确认成功后，钱包支付密码验证码可选择手机号验证。

### 设置支付密码

`wallet_pay_password_set`

请求 `secure_payload`：

```json
{
  "new_pay_password": "123456",
  "verification_method": "mobile",
  "verify_code": "123456"
}
```

规则：

- 支付密码必须是 6 位数字。
- 服务端只保存盐值哈希，不保存明文。
- 设置或修改支付密码必须先通过 `wallet_security_code_send` 获取验证码。
- 设置成功后会清空错误次数和锁定状态。

### 聊天红包/转账支付密码

私聊红包、私聊转账、群聊红包、群聊指定转账仍走 IM 发送接口：

- `im_person_send`
- `im_group_send`

新增强制字段：

```json
{
  "content_type": "transfer",
  "money": "1.00",
  "asset_type": "money",
  "pay_password": "123456"
}
```

```json
{
  "content_type": "red_packet",
  "money": "1.00",
  "asset_type": "money",
  "pay_password": "123456"
}
```

服务端处理顺序：

1. 校验消息发送权限。
2. 校验金额和资产类型。
3. 校验支付密码是否已设置、是否锁定、是否正确。
4. 余额扣减和消息发送进入事务链路。
5. 支付密码错误累计到 3 次后锁定，不再扣款。

### 查询账单

`wallet_bill_list`

请求 `secure_payload`：

```json
{
  "scene": "all",
  "page": "1",
  "limit": "20"
```

- `all`：全部
- `income`：收入

- `withdraw`：提现

### 当前收款码

`wallet_collect_code_current`

请求 `secure_payload`：

```json
{}
```

设置固定金额时：

```json
{
  "amount": "1.23",
  "remark": "选填备注"
}
```

说明：

- 客户端进入收款码页面自动调用。
- `amount` 不传时生成非固定金额收款码，付款方扫码后输入金额。
- `amount` 传入时生成固定金额收款码。
- 付款方扫码后需要输入自己的支付密码。
- 不能扫描自己的收款码。
- 服务端只存 `qr_token_hash`，不明文落库 token。
- 兼容方法：`wallet_collect_code_create`、`wallet_collect_code_update` 内部执行同一逻辑。

### 当前付款码

`wallet_pay_code_current`

请求 `secure_payload`：

```json
{
  "pay_password": "123456"
}
```

说明：

- 客户端进入付款码页面后输入一次支付密码，之后页面内按过期时间自动刷新。
- 不再提前填写收款方和金额。
- 二维码短时有效，只能消费一次。
- 任意非本人用户扫码后输入收款金额并确认收款。
- 服务端确认时扣付款方余额并给扫码方入账。
- 兼容方法：`wallet_pay_code_create` 内部执行同一逻辑。

### 扫码预览订单

`wallet_qr_scan`

请求 `secure_payload`：

```json
{
  "qr_token": "二维码token"
}
```

说明：

- 收款码内容是 `bim://wallet/collect?token=...`。
- 付款码内容是 `bim://wallet/pay?token=...`。
- 服务端只存 `qr_token_hash`，不明文落库 token。

### 确认扫码收付款

`wallet_qr_pay_confirm`

收款码付款请求：

```json
{
  "qr_token": "二维码token",
  "amount": "1.23",
  "pay_password": "123456",
  "request_id": "wallet_1783514188123456_a1b2c3d4"
}
```

付款码收款请求：

```json
{
  "qr_token": "二维码token",
  "amount": "1.23",
  "request_id": "wallet_1783514188123456_a1b2c3d4"
}
```

说明：

- 收款码：扫码用户是付款方，必须输入支付密码；如果收款码已固定金额，服务端以订单金额为准。
- 付款码：扫码用户是收款方，必须输入收款金额；服务端直接扣付款方余额并入账给扫码方。
- 订单会锁行处理，已支付、取消、过期订单不能重复消费。
- 同一订单同一 `request_id` 重试会返回同一结果，不会重复扣款。
- 操作成功后，服务端分别给付款方和收款方发送“支付通知”服务号消息；该通知不进入好友私聊。

## 数据表

新增表：

- `mr_wallet_pay_password`：支付密码盐值和哈希。
- `mr_wallet_order`：扫码收付款订单。

已调整字段：

- `mr_user.money`：`DECIMAL(18,2)`
- `mr_km.money`：`DECIMAL(18,2)`
- `mr_wallet_order.amount`：`DECIMAL(18,2)`
- `mr_wallet_order.payee_id`：`BIGINT NOT NULL DEFAULT 0`，支持动态付款码扫码后再写入收款方。
- `mr_wallet_order.confirm_request_id`：确认支付幂等号。
- `mr_wallet_pay_password.failed_count`：支付密码连续错误次数。
- `mr_wallet_pay_password.locked_until`：锁定截止时间，当前锁定由后台解锁。
- `mr_wallet_pay_password.last_failed_time`：最后错误时间。
- `mr_wallet_pay_password.reset_time/reset_admin_id`：后台重置记录。
- `mr_wallet_pay_password.unlock_time/unlock_admin_id`：后台解锁记录。
- `mr_withdrawal_record.withdraw_fee`：`DECIMAL(18,2)`

```bash
cd /www/wwwroot/blin
mysql -h127.0.0.1 -P3306 -ublin -p123456 blin < database_wallet_migration.sql
```

迁移后需要确认字段：

```sql
SHOW COLUMNS FROM mr_user LIKE 'money';
SHOW COLUMNS FROM mr_km LIKE 'money';
SHOW COLUMNS FROM mr_withdrawal_record LIKE 'withdraw_fee';
SHOW COLUMNS FROM mr_wallet_order LIKE 'amount';
SHOW COLUMNS FROM mr_wallet_order LIKE 'payee_id';
SHOW COLUMNS FROM mr_wallet_order LIKE 'confirm_request_id';
SHOW COLUMNS FROM mr_wallet_pay_password LIKE 'failed_count';
SHOW COLUMNS FROM mr_wallet_pay_password LIKE 'locked_until';
```

金额字段应为 `decimal(18,2)`，`payee_id` 默认值应为 `0`，`confirm_request_id`、`failed_count`、`locked_until` 应存在。

## 已验证

- `wallet_balance` 成功响应为密文，原始响应不包含余额明文。
- 解密后余额保留两位小数，例如 `36.00`。
- 明文提交 `amount=1.23` 会被拒绝。
- `wallet_collect_code_current` 不传金额可自动生成收款码。
- `wallet_collect_code_current` 接受 `1.23`。
- `wallet_collect_code_current` 拒绝 `1.234`。
- `wallet_pay_code_current` 不再要求收款方和金额。
- `wallet_bill_list` 返回标准 `amount` 和 `amount_label`，不再由客户端猜金额。
- `wallet_bill_detail` 可查看账单详情。
- 测试创建的收款码订单已取消，没有留下待支付测试订单。
